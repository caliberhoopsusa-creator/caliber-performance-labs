# Caliber Performance Labs — Codebase Audit (2026-07-01)

Read-only audit of the Replit-exported full-stack app (React 18 + Vite client, Express + Drizzle/Postgres server). No source files were modified. `attached_assets/` was intentionally absent; three 1x1 placeholder PNGs were created temporarily to verify the build and removed afterward.

## 1. Build Health

| Step | Result | Notes |
|---|---|---|

### npm ci failures
1. **Peer-dependency conflict** — `@react-three/drei@^10.7.7` requires `react@^19`, project pins `react@^18.3.1` (`package.json`). Blocks any plain `npm ci`/`npm install`. Fix: pin `drei@^9`, upgrade to React 19, or commit an `.npmrc` with `legacy-peer-deps=true`.
2. **Lockfile out of sync** — `npm ci --legacy-peer-deps` still fails: `Missing: caniuse-lite@1.0.30001800 from lock file`. `package-lock.json` needs regeneration.

### Tests
All test files are supertest integration tests that mount the real app (`tests/helpers/setup.ts` imports `server/routes.ts` → `server/db.ts`, which hard-throws without `DATABASE_URL`). There are **no unit tests** — even `tests/grading.test.ts` and `tests/xp.test.ts` go through HTTP + Postgres. Nothing exercises the pure logic in `shared/ai-rating-engine.ts` (660 lines) in isolation. Test counts: auth 15, players 21, recruiting 18, games 17, referral 12, badges 10, grading 9, xp 7.

### Build
- Real blocker in this export: `client/src/components/CaliberLogo.tsx` (and one other site) import 3 images via the `@assets` alias → `attached_assets/` (`vite.config.ts:26`). Missing files: `caliber-shield-logo.png`, `caliber-logo-orange.png`, `Screenshot_2026-02-11_at_5.31.57_PM_1770916393022.png`.
- With placeholders, full build succeeds in ~11s. Output:
  - `dist/public/assets/index-*.js` — **3,176 kB (807 kB gzip) in a single chunk**. No route-level code splitting anywhere; three.js, `@react-three/*`, `@shadergradient/react`, recharts, framer-motion, and the 3,078-line dead `ModernLandingPage` all ship to every visitor on first paint.
  - `dist/public/assets/index-*.css` — 330 kB (47 kB gzip).
  - `dist/index.cjs` — 1.9 MB server bundle (esbuild, `script/build.ts`).

## 3. Dead Code / Risk Map

### Security — CRITICAL
This is a youth-sports platform; the identity/authz gaps matter more than usual. `server/routes.ts` defines **514 endpoints**; a large "social" band of them predates the auth system and still uses client-supplied identity.

1. **Direct messages are completely unauthenticated** (`server/routes.ts:7093-7160+`). Anyone can: create threads between arbitrary players (`POST /api/dm/threads`), **read any thread's messages** (`GET /api/dm/threads/:threadId/messages` — no participant check, no login), and **send messages impersonating any player** (`POST .../messages` takes `senderPlayerId` from the request body). On a platform with minors this is the single most urgent fix.
2. **Unauthenticated destructive endpoint**: `DELETE /api/games/:id` (`server/routes.ts:4337-4340`) deletes any game with no auth check whatsoever.
3. **Spoofable identity across the social layer**: game likes/comments (`4146`, `4198`), feed reactions/comments/reposts (`6780`, `6863`, `6958`), polls and votes (`7280`, `7327`), predictions (`7411`), stories views/reactions/tags (`7644+`), player highlights (`7869`), XP-granting activity pings (`POST /api/players/:id/activity`, `3947` — free XP/coins for any player id). Identity = whatever `sessionId`/`createdBy`/`playerName` the client sends; comment deletion authz is "knows the sessionId" (`4220`).
4. **Stripe webhook verification fallback**: when `STRIPE_WEBHOOK_SECRET` is absent, `server/webhookHandlers.ts:38-44` falls back to `JSON.parse` of the raw body **without signature verification** and then credits coin purchases (`handleCoinPurchase`). A forged POST to `/api/stripe/webhook` can mint coins. (The route is also exempted from the API rate limiter, `server/index.ts:150`.)
5. **Admin auth design**: `POST /api/admin/login` compares with `===` (not timing-safe, unlike the `isAdmin` middleware at `routes.ts:26-50`) and the client then stores the admin password in **localStorage** (`client/src/pages/Admin.tsx:69-70`), replaying it as an `x-admin-password` header. Mitigated by the port-gating: `/api/admin/*` is 403'd on the public port and only served on the 127.0.0.1-bound admin listener (`server/index.ts:123-130, 272-277`) — a genuinely nice pattern — but the password-in-localStorage handling should still go.
6. **Positives worth keeping**: helmet (CSP intentionally off, `index.ts:118`), rate limits on auth (20/15min) and API (100/min), scrypt password hashing with timing-safe compare, zod validation on most newer endpoints, no secrets committed, no `.env` in the repo, timing-safe partner API keys.

### Bug (runtime, found by reading — worth confirming)
- `GET /api/admin/analytics` player-stats SQL has a **trailing comma before `FROM`** (`server/routes.ts:9621-9623`: `... as basketball_players,\n FROM players`) — that query throws a syntax error at runtime, likely 500-ing part of the admin dashboard.

### Dead code
- **`client/src/pages/ModernLandingPage.tsx` (3,078 lines)** — imported in `client/src/App.tsx:35`, never rendered (unauthenticated root renders `Landing`, `App.tsx:276`). Ships in the bundle.
- **`server/replit_integrations/chat/`, `image/`, `batch/`** — never imported outside their own folders; unwired Replit template code.
- **`openid-client`** dependency — unused (auth is passport-local).
- **`ws`** dependency + esbuild allowlist entry (`script/build.ts`) — no WebSocket server exists anywhere; all "live" features poll.
- **`shared/football-archetypes.ts`** — a 1-line `export {}` stub (multi-sport ambition, unbuilt).
- `landing-full.png`, `admin-page.png` at repo root — screenshots checked into source.

### Oversized files (maintainability risk)
- `server/routes.ts` — **19,823 lines / 514 endpoints** in one function. Every merge conflict, every review, every AI-assisted edit pays for this.
- `server/storage.ts` — 4,255 lines, ~445 methods on one storage class.
- `shared/schema.ts` — 3,078 lines / 117 tables (plus 6 in `shared/models/`).
- Client: `PlayerDetail.tsx` 4,165 lines, `FeedContent.tsx` 2,173, `use-basketball.ts` 1,000+.

## 4. Future-Forward Upgrade Roadmap

Grounded in what exists. Effort: S (≤1 day), M (days), L (weeks).

### P0 — Trust & foundation (nothing else matters if these are wrong)
1. **Close the authz holes (S/M)** — Add `isAuthenticated` + participant/ownership checks to DMs, game delete, and the social layer; derive identity from `req.user`, never the body. The middleware (`isAuthenticated`, `canModifyPlayer`, `routes.ts:96`) already exists — this is wiring, not architecture. *Unlocks: the safety story a youth recruiting platform must have before growth.*
2. **Repo hygiene (S)** — Regenerate lockfile, resolve the drei/React-19 peer conflict, commit `.env.example`, move the 3 logo PNGs out of `attached_assets/` into `client/src/assets/`. *Unlocks: anyone (or any CI) can build.*
3. **CI + unit tests (S/M)** — No CI config exists (only `.replit`). GitHub Actions with a Postgres service container runs the existing 109 integration tests as-is; extract pure-function unit tests for `shared/ai-rating-engine.ts` and `shared/archetypes.ts`. Fix the admin analytics SQL and add a regression test. *Unlocks: safe iteration speed.*
4. **Stripe portability + webhook hardening (S)** — `STRIPE_SECRET_KEY` env fallback in `stripeClient.ts`; refuse unverified webhook payloads for coin credits. *Unlocks: deploy anywhere; un-forgeable revenue events.*

### P1 — Product differentiation ("future of basketball" bets)
5. **Real-time layer: WebSockets over polling (M)** — Live game mode is complete CRUD (`/api/live-game/*`, `routes.ts:11690-11990`, spectator tables `schema.ts:1355-1550`) but spectators poll every 5s (`use-basketball.ts:1002`) and DMs poll at 3-5s (`MessagesPage.tsx:100,114`). `ws` is already a dependency and already in the server-bundle allowlist. A single socket hub for live-game events, spectator counts, DMs, and notifications turns "refresh-feeling" features into genuinely live ones. *Unlocks: watchable live games — the wedge feature for parents/scouts who can't attend.*
6. **AI video pipeline v2 (L)** — Today: one synchronous request holds the HTTP connection while a ≤50MB base64-inlined video goes to `gemini-2.5-flash` with a 60s timeout and 3 retries (`routes.ts:5181-5340`). The prompt engineering (confidence/videoQuality/limitations fields) is genuinely good. Upgrade path: (a) upload via the existing object-storage presigned flow instead of multer→base64 in RAM; (b) async job queue with status polling/socket push; (c) Gemini Files API to lift the 50MB/short-clip ceiling to full games; (d) persist per-event timestamps, not just aggregate stats. *Unlocks: full-game analysis, the core paid feature made reliable.*
7. **Shot-chart data moat (M)** — A `shots` table with x/y court coordinates (0-100) per shot, type, quarter already exists (`shared/schema.ts:942-955`) plus `ShotChartPage.tsx`/`LogShotModal.tsx`. Bridge #6 → #7: have video analysis emit shot locations, and make live-game logging capture tap-to-court coordinates. Aggregate into zone efficiency, and you own longitudinal shot-profile data nobody at the youth level has. *Unlocks: defensible data asset; recruiter-grade scouting reports.*
8. **Recruiting marketplace dynamics (M/L)** — The supply side is unusually deep already: college DB with rosters/coaching staff/stats seeds (`server/seeds/`), `playerCollegeMatches`, `recruiterProfiles` + `recruiterProfileViews` (the "Who's Watching" page), `recruiterNotes`, `recruitPosts`/`recruitInterests`, NCAA eligibility tracking, and verified stats (`statVerifications`, coach endorsements). What's missing is the flywheel: recruiter-side search alerts ("new 6'2 PG with verified 20ppg"), player-side "profile viewed by D2 coach" push notifications, and a verification badge tier that makes Caliber-verified stats the currency. *Unlocks: two-sided network effects; recruiter subscriptions as a second revenue line.*
9. **Wearables beyond Fitbit (M)** — Schema anticipates `fitbit | google_fit | whoop | apple_health` (`schema.ts:2362`); only Fitbit OAuth is implemented (`routes.ts:15827+`). Add Whoop/Garmin OAuth (similar shape), and note Apple Health requires a native shell (see #10). Fuse load/recovery data with the game-performance and practice data already collected. *Unlocks: player-development story (load vs. performance) no stat-tracker competitor has.*

### P2 — Reach & polish
10. **PWA → installable mobile excellence (M)** — Manifest + service worker exist and are sane (network-first scripts, cache-first images, `client/public/sw.js`), with `InstallPrompt`, `OfflineBanner`, pull-to-refresh components. Gaps: no offline mutation queue (a coach courtside with bad gym Wi-Fi loses live-game events), no push notifications (server `notifications` table exists — wire Web Push), no background sync. If Apple Health or App Store presence matters, wrap in Capacitor and reuse everything. *Unlocks: courtside reliability — the actual usage context.*
11. **Bundle diet + code splitting (S/M)** — Delete `ModernLandingPage` import, `React.lazy` per route group, and lazy-load three.js/`@shadergradient` (landing-only) and recharts (analytics-only). 807 kB gzip → plausibly <250 kB initial. *Unlocks: mobile first-paint; SEO for the public landing/blog/player-profile pages.*
12. **Decompose the monoliths (M, ongoing)** — Split `server/routes.ts` by domain (auth, players, games, live, social, recruiting, admin, billing, wearables — the file's own comment banners already mark the seams) and `storage.ts` into per-domain repositories. Expand the typed contract pattern started in `shared/routes.ts` (only games/players use it) so client and server share one API definition. *Unlocks: parallel development; the single highest-leverage maintainability fix.*
13. **Observability (S)** — Sentry is already wired on both sides behind `SENTRY_DSN` (`server/index.ts:17`, `client/src/main.tsx:9`); set the DSN, add release tagging in `script/build.ts`, and a `/healthz` endpoint for uptime checks. *Unlocks: knowing about the admin-analytics-style 500s before users do.*
14. **Multi-sport foundation, decided deliberately (L or delete)** — `shared/sports-config.ts` and manifest copy promise football; `football-archetypes.ts` is empty. Either invest (football film analysis via the same Gemini pipeline is a real expansion) or strip the stubs to keep the basketball story sharp.

### Suggested sequence
Quarter 1: items 1-4 (trust + foundation) and 11 (quick win). Quarter 2: 5 + 6 (live + video are the product). Quarter 3: 7 + 8 (data moat + marketplace). Ongoing: 12.
